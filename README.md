# api-microservice-go-archetype

[![CI](https://github.com/vladeParica/api-microservice-go-archetype/actions/workflows/ci.yml/badge.svg)](https://github.com/vladeParica/api-microservice-go-archetype/actions/workflows/ci.yml)
[![Go Reference](https://pkg.go.dev/badge/github.com/vladeParica/api-microservice-go-archetype.svg)](https://pkg.go.dev/github.com/vladeParica/api-microservice-go-archetype)
[![License](https://img.shields.io/badge/license-Apache%202.0-blue.svg)](LICENSE)

A production-ready template for building HTTP API microservices in Go. It favors
the standard library and idiomatic Go, and includes PostgreSQL access,
structured logging, configuration, health probes, graceful shutdown, tests, CI
and container tooling.

## Features

- **Standard library HTTP routing** with Go 1.22 method and path patterns (`net/http.ServeMux`).
- **Structured logging** with `log/slog`, including a request id on every log line.
- **Type-safe SQL** generated by [sqlc](https://sqlc.dev) on top of [pgx v5](https://github.com/jackc/pgx).
- **Versioned migrations** with [golang-migrate](https://github.com/golang-migrate/migrate).
- **Configuration** from YAML with environment variable overrides via [Viper](https://github.com/spf13/viper).
- **Operational endpoints**: liveness (`/healthz`) and readiness (`/readyz`) probes.
- **Graceful shutdown** on `SIGINT`/`SIGTERM`, server timeouts and panic recovery.
- **Clean layering**: handler → service → repository, with no global state.
- **Tooling**: Makefile, golangci-lint, GitHub Actions, Dependabot, distroless Docker image.

## Project layout

```text
.
├── api/                  # HTTP request samples (and API specs, if any)
├── cmd/api/              # Application entry point (wiring only)
├── configs/              # Default configuration files
├── db/
│   ├── migrations/       # golang-migrate SQL migrations (up/down)
│   └── queries/          # SQL queries consumed by sqlc
└── internal/
    ├── config/           # Configuration loading and validation
    ├── database/         # sqlc generated code (do not edit)
    ├── health/           # Liveness and readiness probes
    ├── httpx/            # JSON request/response helpers
    ├── logger/           # slog setup and context propagation
    ├── postgres/         # Connection pool factory
    ├── server/           # HTTP server and middleware
    └── user/             # Example resource: model, service, repository, handler
```

The layout follows the conventions described in the official
[Organizing a Go module](https://go.dev/doc/modules/layout) guide. Application
code lives under `internal/` so that it cannot be imported by other modules.

## Getting started

### Prerequisites

- [Go 1.22+](https://go.dev/dl/)
- [Docker](https://docs.docker.com/get-docker/) with Compose
- Optional: [sqlc](https://docs.sqlc.dev/en/latest/overview/install.html), [golangci-lint](https://golangci-lint.run/welcome/install/), `make`

### Create a new service from this template

```bash
go install golang.org/x/tools/cmd/gonew@latest
gonew github.com/vladeParica/api-microservice-go-archetype github.com/your-org/your-service
```

### Run with Docker Compose

Starts PostgreSQL, applies the migrations and runs the API on port `8080`:

```bash
make up          # docker compose up --build -d
curl localhost:8080/readyz
```

### Run locally

```bash
docker compose up -d postgres migrate   # database + migrations
make run                                # go run ./cmd/api
```

Run `make help` to list every available task.

## Configuration

Configuration is read from [`configs/config.yaml`](configs/config.yaml) (path
configurable with `-config`). The file is optional: every key has a default and
can be overridden with an environment variable built from its upper-cased path
joined by underscores.

| Variable            | Default            | Description                              |
|---------------------|--------------------|------------------------------------------|
| `APP_NAME`          | `api-microservice` | Service name added to every log line     |
| `APP_ENVIRONMENT`   | `local`            | Deployment environment                   |
| `HTTP_PORT`         | `8080`             | Listening port                           |
| `HTTP_SHUTDOWN_TIMEOUT` | `10s`          | Grace period for in-flight requests      |
| `LOG_LEVEL`         | `info`             | `debug`, `info`, `warn` or `error`       |
| `LOG_FORMAT`        | `json`             | `json` or `text`                         |
| `DATABASE_HOST`     | `localhost`        | PostgreSQL host                          |
| `DATABASE_PORT`     | `5432`             | PostgreSQL port                          |
| `DATABASE_USER`     | `postgres`         | PostgreSQL user                          |
| `DATABASE_PASSWORD` | _(empty)_          | PostgreSQL password                      |
| `DATABASE_NAME`     | `postgres`         | PostgreSQL database                      |
| `DATABASE_SSLMODE`  | `disable`          | PostgreSQL SSL mode                      |
| `DATABASE_MAX_CONNS`| `10`               | Maximum pool size                        |

## API

| Method | Path                 | Description                     |
|--------|----------------------|---------------------------------|
| `GET`  | `/healthz`           | Liveness probe                  |
| `GET`  | `/readyz`            | Readiness probe (checks the DB) |
| `POST` | `/api/v1/users`      | Create a user                   |
| `GET`  | `/api/v1/users/{id}` | Get a user by id                |

Errors are returned as `{"error": "<message>"}` with the appropriate status
code. Sample requests are available in [`api/requests.http`](api/requests.http).

```bash
curl -X POST localhost:8080/api/v1/users \
  -H 'Content-Type: application/json' \
  -d '{"name":"John","email":"john@example.com"}'
```

## Development

### Adding a new resource

1. Create a migration: `make migrate-new name=create_orders`.
2. Write the queries in `db/queries/orders.sql` and run `make sqlc`.
3. Add a package under `internal/orders` with its model, repository, service and handler
   (use `internal/user` as a reference).
4. Register the handler routes in [`cmd/api/main.go`](cmd/api/main.go).

### Quality checks

```bash
make fmt     # gofmt
make vet     # go vet
make lint    # golangci-lint
make test    # go test -race ./...
```

CI runs linting, tests with the race detector, a check that the sqlc generated
code is up to date, and a Docker build on every push and pull request.
